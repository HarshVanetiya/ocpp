Day 14 — Go live

Goal: run on one VPS with HTTPS/WSS, Telegram in webhook mode, real Razorpay keys, and a first real charger.

Tasks

1. Telegram webhook

apps/api/src/index.ts — replace bot.start(...)
import { webhookCallback } from "grammy";

if (env.PUBLIC_URL) {
  app.post("/webhooks/telegram", express.json(), webhookCallback(bot, "express", { secretToken: env.TELEGRAM_WEBHOOK_SECRET }));
  await bot.api.setWebhook(`${env.PUBLIC_URL}/webhooks/telegram`, { secret_token: env.TELEGRAM_WEBHOOK_SECRET });
} else {
  bot.start(); // local dev
}
Add TELEGRAM_WEBHOOK_SECRET: z.string().optional() to env.ts. Telegram only allows A–Z a–z 0–9 _ - in it (e.g. openssl rand -hex 32).

2. Offline watchdog + stuck sessions

apps/api/src/jobs.ts
import { prisma } from "@ev/db";

export function startJobs() {
  // No heartbeat for 3 minutes → offline
  setInterval(() => prisma.chargePoint.updateMany({
    where: { isOnline: true, lastSeenAt: { lt: new Date(Date.now() - 3 * 60_000) } },
    data: { isOnline: false },
  }), 60_000);
}

// Server restarted while sessions were PENDING → their timers are gone
export const failStalePending = () => prisma.chargingSession.updateMany({
  where: { status: "PENDING", createdAt: { lt: new Date(Date.now() - 2 * 60_000) } },
  data: { status: "FAILED" },
});

Call startJobs() and await failStalePending() in index.ts at startup.

3. Deploy

  • One VPS (2 GB RAM is enough), Docker installed, a domain pointing to it.
  • No Postgres container. The database is the Neon main branch (or Aiven). Use its pooled URL as DATABASE_URL.
  • docker-compose.yml on the server has only api, web and caddy. The api image comes from GHCR (built by your Day 2 workflow), so nothing is built on the server.
  • Caddy gives free HTTPS and proxies WebSockets automatically.
docker-compose.yml (on the server)
services:
  api:
    image: ghcr.io/YOUR_GITHUB_USER/ev-api:latest   # lowercase; use a :COMMIT_SHA tag to pin a version
    restart: unless-stopped
    env_file: .env.api          # DATABASE_URL, JWT_SECRET, TELEGRAM_*, RAZORPAY_*, PUBLIC_URL ... (never in git)
    environment:
      PORT: 4000
  web:
    image: ghcr.io/YOUR_GITHUB_USER/ev-web:latest   # or host the dashboard on Vercel instead and delete this service
    restart: unless-stopped
    environment:
      API_URL: http://api:4000
  caddy:
    image: caddy:2
    restart: unless-stopped
    ports: ["80:80", "443:443"]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - caddy_data:/data
volumes:
  caddy_data:
The dashboard (apps/web) is easiest on Vercel, which needs no Docker. If you'd rather containerise it too, use the same pattern as the API Dockerfile with Next.js output: "standalone", and add a second job to the Day 2 workflow.

Migrations

Run migrations from your PC or from CI against Neon's direct URL, not inside the API container (the image has no Prisma CLI, and with several containers they would race each other).

Caddyfile
ev.example.com {
  handle /ocpp/*     { reverse_proxy api:4000 }
  handle /webhooks/* { reverse_proxy api:4000 }
  handle             { reverse_proxy web:3000 }
}
terminal (your PC, PowerShell) — migrate the production branch first
$env:DATABASE_URL = "<Neon main-branch DIRECT url>"
$env:DIRECT_URL   = $env:DATABASE_URL
pnpm --filter @ev/db exec prisma migrate deploy
terminal (on the server) — deploy or update
docker compose pull
docker compose up -d

Scaling to more than one API container

The code is built so one container works. Before you run two or more, fix these (all are in-memory today):

  • OCPP sockets: a charger is connected to exactly one container. A bot press handled by another container cannot reach it. You need a way to route RemoteStart/Stop to the container that owns the socket (e.g. Redis pub/sub keyed by ocppId), or a single container for OCPP and many for everything else.
  • Background jobs (startJobs): every container would run them. Run them in one container only (an env flag such as RUN_JOBS=true), or make them safe to repeat.
  • Telegram: webhook mode (above) already works with many containers, but long polling does not.
  • Bot throttle / live-message state kept in memory must move to the database or Redis.
  • Connections: each container opens a Prisma pool. Keep the pooled Neon URL and set connection_limit=5 on it so N containers stay under the database limit.
  • Charger URL to configure on hardware: wss://ev.example.com/ocpp/<ocppId>
  • Set API_URL=http://api:4000 for the web container.
