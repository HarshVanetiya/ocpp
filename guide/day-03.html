Day 3 — Tenant isolation

Goal: a tenantDb(tenantId) client that automatically adds tenantId to every query, so a tenant admin can never touch another tenant's rows.

How it works

prisma.$extends({ query }) lets you intercept every query before it runs. We add where.tenantId on reads/updates/deletes and data.tenantId on creates.

  • Tenant models (have tenantId): ChargePoint, TenantMembership, ChargerTariffRule, ChargingSession
  • Connector has no tenantId → filter through its charger: chargePoint: { tenantId }
  • Everything else (User, Tenant, AdminUser, Payment) → blocked in tenantDb. Tenant routes have no reason to touch them directly.

Tasks

packages/db/src/tenantDb.ts
import { prisma } from "./client";

const TENANT_MODELS = new Set(["ChargePoint", "TenantMembership", "ChargerTariffRule", "ChargingSession"]);
const WHERE_OPS = new Set([
  "findUnique", "findUniqueOrThrow", "findFirst", "findFirstOrThrow", "findMany",
  "count", "aggregate", "groupBy", "update", "updateMany", "delete", "deleteMany",
]);

export function tenantDb(tenantId: string) {
  return prisma.$extends({
    query: {
      $allModels: {
        async $allOperations({ model, operation, args, query }) {
          const a = (args ?? {}) as any;

          if (model === "Connector") {
            if (WHERE_OPS.has(operation)) a.where = { ...a.where, chargePoint: { tenantId } };
            else throw new Error(`Connector.${operation} not allowed in tenantDb`);
            return query(a);
          }

          if (!TENANT_MODELS.has(model)) {
            throw new Error(`${model} is not accessible from tenantDb`);
          }

          if (WHERE_OPS.has(operation)) a.where = { ...a.where, tenantId };
          if (operation === "create") a.data = { ...a.data, tenantId };
          if (operation === "createMany") {
            a.data = [].concat(a.data).map((d: object) => ({ ...d, tenantId }));
          }
          if (operation === "upsert") {
            a.where = { ...a.where, tenantId };
            a.create = { ...a.create, tenantId };
          }
          return query(a);
        },
      },
    },
  });
}

export type TenantDb = ReturnType<typeof tenantDb>;
packages/db/src/index.ts — add
export { tenantDb, type TenantDb } from "./tenantDb";
Always pass tenantId as a plain field. Never use tenant: { connect: ... } with tenantDb — it will conflict with the injected tenantId.
include / nested relations are not filtered. Query tenant models at the top level. Example: load chargers with tenantDb(...).chargePoint.findMany({ include: { connectors: true } }) — fine, because the connectors belong to a charger you already own.

Test it

Create a second tenant + charger in Prisma Studio (e.g. CP_OTHER), then:

packages/db/scripts/isolation-check.ts
import { prisma, tenantDb } from "../src";

async function main() {
  const tata = await prisma.tenant.findUniqueOrThrow({ where: { slug: "tata-fleet" } });
  const db = tenantDb(tata.id);

  console.log(await db.chargePoint.findMany({ select: { ocppId: true } }));       // only CP_TEST01
  console.log(await db.chargePoint.findFirst({ where: { ocppId: "CP_OTHER" } })); // null
  await db.user.findMany().catch((e) => console.log("blocked:", e.message));     // throws
}

main().finally(() => prisma.$disconnect());
